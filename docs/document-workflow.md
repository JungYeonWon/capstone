# 맞춤 서류 작성 개선 — 2026-11-05

## 사용 흐름

1. 계약 → 맞춤 초안에서 과업수행계획서·제안서·보고서·확약서를 선택하고 필요한 내용을 입력합니다. 같은 기관·사업·문서 종류의 지정 양식이 있으면 먼저 확인합니다.
2. 제목·항목·순서·필수 여부·표 구성을 검토하여 초안을 만듭니다. 보고서의 실제 성과와 확약 내용은 계약 설명으로 임의 확정하지 않습니다.
3. 편집기의 **부족한 정보 질문 확인**에서 확인된 내용을 답변합니다. 표는 칸별로 입력하고 행을 추가·삭제합니다(최대 50행). 모르는 내용은 빈칸으로 둡니다.
4. **로컬 초안 제안**은 답변·계약 정보·공통 문장을 사용합니다. **AI 본문 제안**은 전송할 내용을 확인하고 이번 요청에 동의한 경우에만 호출합니다. 결과는 항목별로 반영하며, 기존 입력을 대체할 때 확인합니다. AI 문장은 검토용 표시가 붙습니다.
5. **저장하고 미리보기**로 확정 저장한 뒤 HWPX·PDF를 내려받습니다. 미저장 수정이 있으면 개별 다운로드는 비활성화됩니다. 임시 저장 내용은 확정 저장·출력과 구분합니다.

## 임시 저장·복원

- 맞춤 구성, 질문 답변, 문서 편집 내용, 제출 체크리스트는 계약 소유자만 접근 가능한 서버 DB에 암호화 저장합니다. 브라우저 localStorage에 문서 본문을 저장하지 않습니다.
- 수정 후 약 0.9초에 저장하며 저장 상태·실패를 표시합니다. 새로고침하면 구성·답변·체크리스트가 복원됩니다. 문서 편집본은 명시적인 복원 버튼을 제공합니다. 마지막 확정 저장 시점과 다르면 주의를 표시합니다.
- 여러 창에서 같은 초안을 바꾸면 revision을 검사하고, 오래된 창의 덮어쓰기를 409로 차단합니다. 충돌 시 입력을 복사한 뒤 새로 불러와 비교하세요.
- 서버에 보내기 전 창을 닫으면 마지막 입력 일부가 유실될 수 있습니다. 저장 완료 상태를 확인하세요. 체크리스트를 제외한 임시 작업본은 30일간 수정이 없으면 정기 정리합니다. 계약 삭제·내 데이터 삭제 시 작업본도 함께 삭제됩니다.

## 제출 안내문과 통합 점검

- 안내문 텍스트(최대 20,000자) 또는 텍스트 PDF(3MB·20페이지 이하)를 가져옵니다. PDF 원본은 저장·외부 전송하지 않고 추출 텍스트만 사용합니다. 스캔 OCR은 지원하지 않습니다.
- 로컬 분석은 알려진 서류명과 목록 문장을 추출합니다. 선택적 AI 분석은 동의한 마스킹 텍스트만 사용하고, 원문 인용 근거가 있는 항목만 추가합니다. 자동 분석은 완전하지 않으므로 목록·제출기한·조건을 원문과 대조하세요.
- 목록은 최대 30개이며 이름·필수 여부·준비 상태·메모·연결 서류를 수정할 수 있습니다. 재분석은 기존 수동 항목과 확인 상태를 조용히 삭제하지 않습니다. 등록된 관련 양식 링크를 제공합니다. 외부 첨부는 수동 준비 항목으로 관리합니다.
- 계약의 **제출 전 통합 점검**은 기존 누락·금액·기간·교차 검증 외에 검토용/미정 문구, 표 형식·빈칸, 미완료 체크리스트, 미반영 임시 저장을 보여줍니다. 준비 체크나 자동 점검 통과는 실제 제출 완료·발주처 승인·법적 적합성 확인을 의미하지 않습니다.

## 양식 버전 관리

- 내 맞춤 양식 → 구성 보기 → **복제·새 버전 구성 편집**에서 제목·항목·순서·표 열을 수정합니다. 변경 메모와 구성 확인 후 새 개인 양식으로 저장합니다.
- 기존 템플릿을 수정하지 않고 root/parent/version 메타데이터로 이력을 연결합니다. 기존 서류는 원래 템플릿 ID를 유지하여 당시 구성을 보존합니다. 문서별 입력값·타 회사 비공개 자료는 복제하지 않습니다. 모든 버전을 합쳐 기존 계정당 50개 제한을 적용합니다.

## 운영 반영

- **배포 전 DB 관리자가 `docs/workspace-schema.sql`을 적용해야 합니다.** `workspace_states` 테이블 1개와 backend 전용 RLS 정책을 추가합니다. 기존 MFA 테이블과 키 설정도 먼저 반영되어 있어야 합니다. 로컬은 서버 재시작 시 추가됩니다.
- 자동 작성에는 FastAPI 서버가 읽는 `OPENAI_API_KEY`와 `OPENAI_MODEL`이 필요합니다. 로컬 `.env`와 Vercel Production 환경변수는 별개입니다. 키는 Git에 넣지 않으며 브라우저 공개 변수(`NEXT_PUBLIC_*`)로 등록하지 않습니다.
- 외부 AI를 설정하지 않아도 문서 구성·질문·확인된 답변으로 작성·체크리스트·출력·버전 관리는 사용할 수 있습니다. AI 실패 시 대체 여부를 표시합니다. 외부 호출은 재시도 없이 35초 제한과 출력 3,000토큰 상한을 사용하며 `store=False`로 요청합니다. 이것만으로 제공업체의 모든 보관 정책이 제거되는 것은 아닙니다.
- 본문 전송에는 사용자가 확인한 계약 일부 정보, 요청, 해당 문서 항목과 답변이 포함됩니다. 계좌·인감·다른 사용자의 문서를 자동으로 추가하지 않습니다. 일반 마스킹이 모든 영업기밀을 제거하지 않으므로 전송 미리보기를 확인해야 합니다.
- 이번 구현은 운영 DB/사이트를 변경하지 않습니다. API 키의 Vercel 등록·재배포는 권한 있는 팀원이 진행합니다.

## 검증 기록

- 기존 보안·서식 테스트와 신규 통합 테스트 13개를 포함한 전체 86개 통과. 실제 AI 호출을 막은 격리 DB에서 계정 간 접근 차단, 정확한 전송 동의, 암호화 임시 저장, stale revision 충돌, 개인 양식 버전 보존, 체크리스트·표·미확정 문구 점검, 데이터 삭제를 검증했습니다.
- 가상 보고서 내용만으로 실제 OpenAI 본문 제안 1회 성공. 실제 회사·계약 정보나 사용자 DB를 사용하지 않았습니다.
- 별도 DB와 로컬 포트의 브라우저에서 회사·계약 생성 → 구성 제안 → 새로고침 후 구성 복원 → 문서 생성 → 표 칸 입력 → 질문 답변·본문 제안·선택 반영 → 저장·PDF 페이지 미리보기 → 안내문 체크리스트 → 통합 점검 → 개인 양식 새 버전 생성 및 v1/v2 이력까지 확인했습니다.
- Next.js Webpack 배포용 빌드·타입 검사 성공. 린트 오류 없음(기존 API 클라이언트 내비게이션 경고 1개). 운영 클라우드 검증은 포함하지 않습니다.
