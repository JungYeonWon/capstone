# 계약 조항 검토 누락 보완

- AI 결과 상한을 8건에서 20건으로 확대하고, 해당 요청의 출력 예산을 7,000토큰으로 조정했다. 다른 기능의 기본 출력 예산은 유지한다. AI 호출 횟수는 기존과 동일한 1회이며 실제 출력에 따른 비용과 응답 시간이 늘 수 있다.
- 모든 파일·쪽을 순서대로 확인하고 본문과 별첨의 예외·우선순위·상충 조건을 함께 검토하도록 명시했다. 자동 갱신, 일방 변경·권리 이전, 재위탁·보안, 비밀유지·데이터, 분쟁·관할까지 점검표와 분류를 확장했다.
- 유효한 AI 응답 이후, 로컬 규칙 8개로 원문을 추가 점검한다. 역할별 무상 무제한 지원, 무료 추가 과업, 넓은 배상 책임, 미정 검수 기한, 자동 갱신, 단독 변경·이전, 자유로운 재위탁, 자료 이용·보관 표현을 확인한다.
- 규칙 후보는 불리함을 확정하지 않는다. 원문 인용, 파일·쪽, 질문과 함께 `규칙 기반 확인 후보`로 표시한다. 화면·저장 이력·질문 복사·PDF에 이 구분을 유지한다. 기존 이력에는 새 분석을 소급 적용하지 않는다.
- AI 인용의 source_id와 원문 일치 검증을 유지한다. 이미 AI가 인용한 같은 부분은 규칙으로 중복 추가하지 않는다. 다른 파일·쪽의 같은 유형은 보존한다. 키·한도·통신 오류는 성공 결과로 위장하지 않는다.
- 부정·예외·상호 합의 표현이 있는 규칙 후보는 보수적으로 제외한다. 문맥을 잘라내지 않도록 8~350자의 문장/줄 단위만 보완한다. 긴 조항, 줄을 넘는 조건, 복잡한 부정 표현은 규칙만으로 다루지 못하므로 AI와 사용자의 문맥 확인이 필요하다.
- 규칙 후보는 최대 24건이다. 초과 건수는 별도로 표시하고 자료를 나누어 재검토하도록 안내한다. 입력은 여전히 계약서·별첨 합계 32,000자이며 추출 경고는 유지된다. 표시할 결과가 없다고 안전을 뜻하지 않는다.

## 검증 범위

`tests/test_contract_review_recall.py`는 합성 계약 문구로 AI가 빈 결과를 반환한 경우의 6개 누락 보완, 정상·부정 문구의 오탐 억제, 역할 차이, 중복 억제, 8건 초과 결과 보존, 가짜 인용 제외, 표시 상한 및 실패 처리를 검증한다. `test_review_history.py`는 후보의 저장·재조회·PDF 구분을 검증한다. 이 테스트는 실제 계약서 전체에 대한 AI 재현율이나 법적 정확도를 측정하는 벤치마크는 아니다.

새 DB 열은 필요 없다. 기존 `clause_reviews` 테이블의 암호화 JSON에 버전·생략 건수·후보 생성 방식을 저장한다. 운영 반영 시에는 변경 코드의 병합과 배포가 필요하다.
