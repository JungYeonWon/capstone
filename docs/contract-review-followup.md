# 계약서 검토 이력과 후속 처리

## 사용하기

1. 역할과 계약서·별첨을 선택하고 전송 텍스트 확인·동의 후 AI 검토를 실행합니다. 성공한 결과는 자동 저장됩니다. 이전에 사라진 결과를 소급 복구하지는 않습니다.
2. **검토 이력**에서 당시 역할·자료·원문 인용·부담·질문과 처리 상태를 다시 엽니다. 왼쪽의 새 입력과 저장된 결과는 별개입니다. 검토 대상 저장 문서가 이후 변경·삭제됐으면 이전 자료라는 안내를 표시합니다.
3. 항목별로 **확인 전 / 상대방 문의 중 / 수정·확인 완료**와 메모(1,000자 이하)를 저장합니다. revision 충돌 시 다른 창의 변경을 덮어쓰지 않습니다. 미저장 입력은 저장 또는 입력 취소 후 이력 이동·새 검토·복사·다운로드를 진행합니다.
4. **미완료 질문 복사 / 전체 질문 복사**로 질문을 모읍니다. 자동 복사가 제한되면 질문 모음에서 직접 복사합니다. 외부 메일·메신저는 자동 발송하지 않습니다.
5. **검토 보고서 PDF**에 당시 계약명·역할·자료·원문 인용·부담·질문과 저장된 상태·메모를 담습니다. PDF에 들어갈 사용자 텍스트는 이스케이프합니다.
6. **수정 전후 비교**에서 저장된 다른 검토 또는 왼쪽에 올린 수정본을 대조합니다. 같은 이름의 유일한 파일이나 단일 파일 한 쌍을 자동 연결합니다. 파일명이 다른 여러 자료는 대응 파일을 직접 지정하세요.

비교는 추가 AI 호출 없이 공백·줄바꿈을 정규화해 이전 인용문의 유지·변경·삭제를 보여줍니다. 인용문 동일은 주변 조항이나 문서 전체가 같다는 뜻이 아닙니다. 모호한 대조 위치, 미연결 파일, 새로 추가된 자료는 따로 표시합니다. 긴 수정 영역은 일부만 표시합니다. 변경·삭제를 문제 해결로 판정하거나 처리 상태를 자동 완료하지 않습니다. 새 의무·주변 조항과 수정본 전체 검토는 별도로 확인하세요.

## 보관과 보안

- AI에 전송한 마스킹 텍스트 스냅샷·결과·역할, 계약명·문서 연결·메모를 `EncryptedJSON`으로 암호화합니다. 원본 파일은 검토 이력에 영구 저장하지 않습니다.
- 계약 소유자만 목록·상세·수정·비교·PDF·삭제에 접근하고 쓰기 요청은 CSRF 검사를 거칩니다. 기존 AI 전송 동의와 인증 오류 표시를 유지합니다.
- 계약당 최대 50개입니다. 사용자 삭제 전까지 보관하고 개별 이력·계약·내 데이터 삭제 시 함께 삭제합니다. 제공업체 백업과 이미 다운로드한 보고서는 별도입니다.
- 처리 완료·PDF·비교는 인감 승인과 독립적입니다. 최종본 확인·재인증·문서 변경 후 재승인을 대체하지 않습니다.

## 운영 반영

**배포 전 DB 관리자가 `docs/review-history-schema.sql`을 적용해야 합니다.** 테이블 `capstone.clause_reviews`와 인덱스·backend 전용 RLS·시퀀스 권한을 추가합니다. 앱에 DDL 권한은 주지 않습니다. 기존 계약·문서는 수정하지 않으며 로컬 SQLite는 서버 시작 시 테이블을 생성합니다.

최신 서버·웹을 함께 배포해야 합니다. 로컬 구현·검증은 운영 DB·사이트를 변경하지 않습니다.

## 검증 실행

- 서버 개발 의존성: `pip install -r requirements-dev.txt`
- 서버: API 키를 빈 환경변수로 설정하고 `python -W ignore::DeprecationWarning -m unittest discover -s tests -q`
- 웹: `node --test tests/*.test.mjs`, `npm run lint`, `npx next build --webpack`
- 소유권·CSRF, 암호화 저장·복원, 이력 불변성, 상태·메모 충돌, 실패 미저장, 문서 변경 감지, 원문 비교, 한글 PDF와 사용자 데이터 삭제를 검증합니다.
